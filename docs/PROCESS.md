# 작업 절차 (에이전트용)

이 저장소에서 일하는 모든 에이전트(Claude Code, Codex, 그 밖)가 따르는 절차다. 규칙은 `AGENTS.md`, 현재 사양은 `docs/SPEC.md`, 결정 기록은 `docs/DECISIONS.md`다. 스킬(superpowers 등)이 있으면 쓰고, 없으면 이 문서대로 한다.

## 시작할 때
1. `AGENTS.md`와 `docs/SPEC.md`만 읽는다. `carryover/reference/`와 옛 저장소 `E:/Prodev/G2B_Helper`는 사용자가 지시했을 때, 특정 결정을 찾을 때만 연다.
2. 브리프의 **목표·읽을 것·끝 기준·하지 말 것**을 확인한다. 끝 기준이 "명령을 돌리면 참/거짓이 나오는 문장"이 아니면 먼저 그렇게 고쳐 사용자에게 보인다.
3. 맡은 폴더를 확인한다. 그 폴더 밖은 읽기만 한다.

## 일하는 중
- 사실(파일 내용, 명령 결과, 화면 동작)은 직접 확인한다. 사용자에게 묻지 않는다.
- 결정(안 중 고르기, 범위, 승인)은 사용자에게 묻는다. 묻는 글은 안·장단·되돌림 비용을 갖춘다.
- 브리프 밖의 일이 보이면 하지 않는다. `DECISIONS.md`에 `나중: <한 줄>`로 적고 넘어간다.
- 구조(DB 테이블·컬럼 규칙·메시지 계약·폴더 경계·사전 필드)를 바꿔야 하면 안 2~3개와 되돌림 비용을 먼저 적고, 사용자 승인 뒤 `DECISIONS.md`에 `승인: <날짜> <내용>`으로 적는다.
- 컬럼은 사전이 정한다. 화면 내용이 DB 구조를 바꾸는 코드는 쓰지 않는다. DB 접근은 `core/gateway.py`만.
- 자체 그리드 편집기를 만들지 않는다. 사이트별 설정(화면 코드·업무키·표 이름)은 코드가 아니라 `dict_*` 데이터다.
- 실제 값(공고번호·금액·업체명·기관명)을 코드·테스트·문서·커밋·로그에 적지 않는다. fixture는 구조만.
- 추출·수집을 바꿨으면 공개 나라장터 화면에서 실제로 돌린 기록(구조만)을 남긴다. 없으면 합치지 않는다.

## 끝낼 때
끝났다고 말하기 전에 아래를 전부 채운다. 하나라도 비면 끝난 것이 아니다.
1. **끝 기준 표**: 항목마다 통과 / 실패 / 미실행, 근거(명령과 출력, 화면 확인 내용).
2. **변경 범위**: `git status`로 바뀐 파일이 맡은 폴더 안에만 있는지. 밖에 있으면 되돌린다.
3. **기록**: `DECISIONS.md`에 이번 세션의 결정·나중·승인 줄. `SPEC.md`가 바뀌었으면 본문을 고쳤는지(덧대지 않음).
4. **인계 3줄**: `상태 / 남은 일 / 막힌 것`. PR 본문 끝에도 같은 3줄.

## 가지와 PR
- 세션 하나 = 가지 하나 = PR 하나. 가지 이름은 `<폴더>/<짧은 목표>`.
- PR 본문: 목표, 끝 기준 표, 실행한 명령, 미검증 범위, 인계 3줄.
- 리뷰 봇 지적에는 `고침` 또는 `안 고침(이유)` 둘 중 하나로만 답한다. 검토는 PR당 1회.

## 검증 명령
- `npm run verify` (tsc, vitest, 빌드)
- `pytest core/tests`
- 추출·수집: `node scripts/probe-public.mjs` 또는 내장 브라우저로 공개 화면 확인
이 명령으로 통과하지 못한 것은 통과가 아니다. 실패·미실행·대상 0건은 통과가 아니다.
