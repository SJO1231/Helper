# 1단계 구현 계획 — 목차와 공통 규칙

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement each sub-plan task-by-task.
> 이 저장소는 subagent-driven을 쓰지 않는다(PLAN 6.8: 총괄이 세션을 손으로 띄움). Steps use checkbox (`- [ ]`) syntax.

**Goal:** 공개 나라장터 화면에서 스냅샷 → 사전 → 저장 → 보기 → 내보내기가 끝까지 돌고 SPEC 8절이 모두 참이 된다.

**Architecture:** 폴더마다 세션 하나, 하위 계획 하나. `shared/`가 계약(타입·스키마·코어 클라이언트)을 먼저 고정하고,
`core/`(Python, SQLite 문지기 + HTTP + Native host), `extension/`(MV3), `viewer/`(확장 페이지)가 그 계약만 보고 병렬로 간다.
마지막에 `scripts/e2e-public.mjs`가 실제 공개 화면에서 전체를 돌린다.

**Tech Stack:** TypeScript·esbuild·vitest·ajv(Node 20), Python 3.11 표준 라이브러리(sqlite3·http.server)·pytest·jsonschema,
Playwright(내장 Chromium), 그리드 라이브러리는 S4에서 고름, xlsx는 exceljs.

**Spec:** `docs/SPEC.md` (현재 사양 200줄). 결정 기록은 `docs/DECISIONS.md`.

## Global Constraints

- 파일 하나는 한 가지 일, 300줄을 넘으면 나눈다. 한 줄 120자 안. 주석은 "왜"만.
- `sqlite3`를 import하는 파일은 `core/gateway.py` 하나. SQL 문장을 만드는 순수 함수는 `core/sql_*.py`에 둬도 된다.
- extension·viewer는 core를 import하지 않는다. 둘이 나누는 코드는 `shared/`에만.
- 화면 코드·업무키·표 이름은 코드에 적지 않는다(`dict_*` 데이터). 시험의 화면 코드는 fixture·e2e 배정에만.
- 공고번호·금액·업체명·기관명 같은 실제 값을 코드·테스트·로그·커밋에 적지 않는다. fixture 값은 `V1`, `0001` 같은 자리표시.
- 값은 원문 글자로 다룬다. `null`·`undefined`만 `''`로 바꾸고 숫자·불은 `String()`. '00'·0·false가 그대로 남는다.
- 코어는 `127.0.0.1`만 듣는다. 포트 기본 8765(`HELPER_PORT`), DB 기본 `%LOCALAPPDATA%/helper/helper.sqlite3`(`HELPER_DB`).
- 요청 머리: `Authorization: Bearer <token>`, `X-Schema-Version: 1`, 쓰기는 `X-Request-Id`. 오류 몸통 `{"error": "..."}`.
- 확장은 `chrome.storage`에 수집 자료를 두지 않는다. 자체 그리드 편집기 금지. 표 라이브러리 기본 기능만.
- 공개 사이트 자동 동작 사이는 1.5초 이상. 등록·제출·삭제·다운로드 버튼은 누르지 않는다.
- 끝 기준 명령: `pytest core/tests`, `npm run verify`, `npm run e2e:public`, `npm run bench:viewer`.

## Review Focus

명세가 말하지 않았지만 쓰는 사람이 가장 먼저 부딪힐 다섯 가지. 시험은 맡은 과제에 넣었다.

1. 코어가 꺼져 있거나 토큰이 바뀐 뒤 수집을 누름 → 조용히 사라지지 않고 "코어 꺼짐"이 보이며, 코어가 다시 뜨면
   새 토큰으로 한 번 다시 붙는다. (shared 과제 2 `offline`, extension 과제 5·6)
2. 추출 도중 사용자가 다른 화면으로 이동 → 반쯤 읽은 결과를 보내지 않고 "화면이 바뀜"으로 거절. (extension 과제 3)
3. 수집 버튼을 빠르게 두 번 → 다른 request_id 둘이 같은 raw를 보내도 capture 1행, 둘째 응답은 same. (core 과제 4)
4. 금액 칸에 쉼표·빈칸·'-'가 섞임 → 정렬이 숫자 순서이고 빈칸은 오름·내림 모두 맨 뒤. (core 과제 6)
5. 업무키 값이 비었거나 `|`가 들어 있음 → 메인을 만들지 않고 rejected와 이유. (core 과제 2)
