# ④ 사전 seed — 형식·배치·적재 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** 이미 있는 자료(data_map 31개, pclm `docs/erp/fields.md`, 옛 v4.1 사전)로 `shared/seed/dict_*.json`을 만들고,
값이 한 글자도 없음을 검사로 보이며, 코어가 그 파일을 사전에 넣는 명령을 둔다.

**Architecture:** 과제 1(형식·검사)은 S5가 끝난 뒤 저장소 세션. 과제 2는 GUIDE ④대로 사람이 터미널에서 `claude -p` 배치를
돌린다(조직 크레딧, Sonnet). 과제 3(적재)은 S2가 합쳐진 뒤 `core/`에 파일 하나를 더한다. seed는 자동으로 들어가지 않고
설치 때 명령으로만 넣는다. 그래서 e2e·bench의 빈 DB는 그대로 빈 사전이다.

**Tech Stack:** TypeScript·vitest·ajv(검사), Python(적재), `claude -p`(배치).

**Spec:** `docs/SPEC.md` 6절(사전 필드, std_key 이름, stages). 공통 규칙은 `2026-10-28-stage1-00-index.md`.

## Global Constraints
index 파일 그대로. 더해서:
- seed 파일에는 키·라벨·타입·코드 뜻·화면 코드·하위 표 ID만. 공고번호·금액·업체명·기관명·사람 이름·연락처는 넣지 않는다.
- 배치의 표준 출력·로그에도 값을 찍지 않는다. 배치 결과 JSON 로그는 저장소 밖에 둔다.
- std_key는 나라장터 필드 ID 그대로(camelCase, 가장 흔한 꼴 하나). 화면별 변형은 alias.
- 공개 시험 화면(13713, 01175, 01033, 01141, 01196)의 stage는 seed에 넣지 않는다.
- 사용자 범위 밖 화면은 `shared/seed/reference/`에만 두고 적재하지 않는다.

### Task 1: seed 형식과 값 검사

**Files:**
- Create: `shared/schema/seed.schema.json`, `shared/seed/README.md`(형식·출처 한 쪽), `scripts/seed/check-seed.ts`
- Create: `shared/seed/fixtures/ok/*.json`, `shared/seed/fixtures/bad/*.json`(구조만, 값은 자리표시)
- Modify: `package.json` (`"seed:check": "tsx scripts/seed/check-seed.ts shared/seed"`, devDependency `tsx`)
- Test: `scripts/seed/check-seed.test.ts`

**Interfaces:**
- Produces:
  - 파일 여섯 개 `dict_key.json`·`dict_alias.json`·`dict_label.json`·`dict_code.json`·`dict_screen.json`·`dict_child.json`,
    각각 `{ "rows": [...] }`. 행 모양은 `shared/types.ts`의 `DictKey`·`DictAlias`·`DictLabel`·`DictScreen`과 같고
    `dict_code`는 `{std_key, code, meaning, scope}`, `dict_child`는 `{site, table_code, alias, stage, typed, key_fields}`.
  - `dict_key.display.source`: `"data_map"`·`"pclm"`·`"v4.1"` 중 하나 이상(근거).
  - `checkSeed(dir: string): { ok: boolean; problems: { file: string; row: number; rule: string }[] }`
    — problems에는 위치와 규칙 이름만, 걸린 값은 담지 않는다.
  - 규칙: 스키마(`additionalProperties: false`), 공고·계약번호 꼴(영문2+숫자 10자리 이상, 숫자-숫자 꼴 번호),
    세 자리 넘는 쉼표 숫자, 사업자번호 꼴 `\d{3}-\d{2}-\d{5}`, 전화번호 꼴, 회사·기관 표지어(`㈜`, `(주)`, `주식회사`,
    `시청`, `군청`, `구청`, `공사`, `공단`)가 라벨·뜻에 있음, 공개 시험 화면에 stage가 있음, std_key가 camelCase 필드 ID 꼴이
    아닌데 `display.source`에 `"ours"`가 없음.

  > 끝 기준: npm run seed:check 종료 코드 0. 하지 말 것: 값 출력, 저장소 밖 파일 수정, 공개 시험 화면에 stage.
