# S4·S6 viewer — 그리드 고르기와 읽기 전용 뷰어 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** 그리드 라이브러리를 숫자로 고르고(S4), 확장 페이지 `viewer.html`이 코어의 어떤 테이블이든 쪽 단위로 읽어
읽기 전용 표로 보이고 CSV·xlsx로 내보내며, `npm run bench:viewer`가 SPEC 8절 속도 문장을 판정한다(S6).

**Architecture:** 뷰어는 테이블 이름을 모른다. `listTables`·`listColumns`·`getRecords`(shared 코어 클라이언트)만 부르고
정렬·필터는 코어에 맡긴다. 라이브러리는 `grid-adapter.ts` 한 파일 뒤에 숨겨, 바꿀 때 그 파일만 고친다.
토큰은 background에 `{kind:'core.connection'}`을 물어 받는다(확장 페이지라 같은 확장).

**Tech Stack:** TypeScript, S4가 고른 그리드 라이브러리(기본 기능만), exceljs(xlsx 쓰기), Playwright Chromium(bench).

**Spec:** `docs/SPEC.md` 3·4.2·8절(bench). 공통 규칙은 `2026-10-28-stage1-00-index.md`.

## Global Constraints
index 파일 그대로. S4는 `spikes/grid/`만, S6은 `viewer/`, `scripts/bench-viewer.mjs`, `scripts/bench/`,
`package.json`의 `bench:viewer`·dependencies만 고친다. 자체 편집기·선택 상태기계를 만들지 않는다.
exceljs를 들이는 이유: 그리드 라이브러리와 무관하게 xlsx를 쓰려면 하나가 필요하고, MIT·순수 JS라 확장 번들에 들어간다.

### Task 5: bench:viewer

**Files:**
- Create: `scripts/bench/seed_synthetic.py`, `scripts/bench-viewer.mjs`, `scripts/bench/measure.mjs`
- Modify: `package.json` (`"bench:viewer": "node scripts/bench-viewer.mjs"`)

**Interfaces:**
- Consumes: `core.gateway.Gateway`(seed 스크립트만, 확장·뷰어 코드가 아님), `dist/extension`.
- Produces: 표준 출력에 기준마다 `{"기준": "...", "크기": "10000x100", "값": 숫자, "참": true|false}` 한 줄,
  하나라도 거짓이면 종료 코드 1.

- [ ] **Step 1: seed 스크립트.** 빈 DB(`HELPER_DB` 임시 파일)에 `dict_key` 100개(`stages ["bid"]`, `as_column 1`,
  타입은 text·money·date 고루), `g2b_bid` N행(값은 자리표시, 금액은 자리 수만 무작위). 인자 `--rows 1000|10000`.
- [ ] **Step 2: bench 스크립트.** 크기마다 seed → `python -m core.service` → Playwright Chromium에 `dist/extension`을 올리고
  `chrome-extension://<고정 key의 id>/viewer.html?table=g2b_bid`를 연다. 잰다:
  - 열 수 == `stages`에 bid가 든 as_column=1 표준키 수(코어 `listColumns` 길이와 비교)
  - `page.goto` 시작부터 첫 쪽 행이 DOM에 그려질 때까지 < 1000ms
  - 머리글 클릭부터 새 첫 행이 그려질 때까지 < 300ms, 필터 적용부터 같음 < 300ms(코어 왕복 포함)
  - `GridHandle.setColumnType`(페이지에 시험용으로 노출한 `window.__bench`)부터 다시 그려질 때까지 < 500ms
  - 휠로 세로 끝·가로 끝까지 훑는 동안 `requestAnimationFrame` 간격의 90% 이상 ≤ 16ms
- [ ] **Step 3: Run** `npm run bench:viewer` → 종료 코드 0, 출력 10줄(5기준 × 2크기) 모두 `"참": true`.
  못 넘으면 원인을 적고 라이브러리 설정을 고친다. 자체 렌더러로 우회하지 않는다.
- [ ] **Step 4: Commit** `git commit -m "S6: bench:viewer"`
