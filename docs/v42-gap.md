## 결정 필요
1. 기간 바꾼 뒤 조회를 자동으로 누를까? 지금은 안 누름(S157). v4.2도 기간은 안 눌렀지만 조회건수는 눌렀다.
2. 조회 단독 버튼을 둘까? v4.2는 업무 탭 맨 위에 있었다.
3. 화면의 엑셀 다운로드를 대신 눌러 주는 버튼을 둘까? (뷰어 내보내기와 다른 기능)
4. 조회건수 목록 선택이 즉시 적용되는 지금 방식을 유지할까? 기본값(v4.2는 100)도 정한다.
5. −1년 첫 누름: v4.2는 1.1~12.31이 아니면 이동 없이 맞추기만 했다. 지금은 곧장 ±1. 이대로 확정할까?
6. 기간을 바꾼 뒤 달력 팝업이 남는지 실측하고 숨길지 정한다.
7. 자동수집(화면 변화·통신 감지 저장)을 둘까? 사양에는 수동 수집만 있고 뺀 이유도 없다.
8. 패널 이동·접기·종료·위치 기억이 필요한가? 지금은 화면을 가려도 치울 수 없다.
9. 연락처·분류번호 테이블을 둘까? 1단계 제외 목록에도 2단계 목록에도 없다.
10. 숨김 키 목록(v4.2 28개)을 dict_key.display로 옮길까, 빈 ref 제외로 충분할까?
11. 열 숨김·순서·폭을 어디서 정하나? 뷰어 편집은 뺐고 dict_key.index는 인덱스 뜻이라 자리가 없다.
12. 미등록 키를 사전으로 올리는 길(승격 UI 또는 명령)을 1단계에 둘까? 지금은 세기만 한다.
13. 사전 편집을 UI 없이 HTTP·seed로만 할까?
14. 백업 복원(가져오기)을 둘까? 지금은 내보내기(VACUUM INTO)만 있다.
15. 코드→뜻 표시를 뷰어가 하나? viewer/main.ts에서는 확인되지 않는다.
16. 수집 이력(RAW 목록·이벤트)을 사람이 볼 화면이 필요한가? g2b_capture를 뷰어 목록에 낼지 확인한다.
17. 통합 보기(접수·입찰·계약을 한 줄로)를 v_* 뷰 말고 뷰어 기능으로 둘까?
